# ADR-0002：V1 4×4 INT8 阵列的数值与事务契约

- 提出日期：2026-10-26（Asia/Shanghai）
- 状态：草案
- 适用阶段：V1 独立计算核
- 相关决策：[ADR-0001](ADR-0001-s0-toolchain.md)（工具链选型）
- 规格正文：[V1 阵列规格](../architecture/v1-array-spec.md)

## 背景与约束

V1 需要明确数值、接口和逐拍协议。V1 的设计要求是：4×4、有符号 INT8、32 位累加、weight-stationary、单任务事务接口；V1 不含 bias、量化、饱和或完整 SoC。顶层事务接口约定为：整矩阵 `req_a/req_b` 在请求握手时进入，整矩阵 `rsp_c` 在响应有效时返回，单任务在途，响应可背压，复位同步高有效。

必须同时满足：

1. PE 在计算期间保持权重不变，激活和部分和逐级传递；不采用单拍组合 GEMM 或仅在其输出端增加延迟的实现。
2. 所有 16 个输出可由逐拍表推导；数据与 valid 的对应关系可验证。
3. 顶层接口不改变；整矩阵接口只作为事务边界，不表示单拍计算。
4. 单任务、无队列；复位取消在途任务；响应背压时完整结果保持。

## 备选方案

| 方案 | 优点 | 代价与约束 | 结论 |
|---|---|---|---|
| A. 单拍组合/并行 GEMM | 延迟最低；接口简单 | 不是脉动阵列，也没有真实权重驻留；不满足 V1 设计约束；时序难以收敛 | 不满足脉动阵列结构要求；不采用 |
| B. Weight-stationary：PE(r,c)=B[r][c]，激活向东、部分和向南 | 权重驻留，矩阵索引与 PE 映射直接对应；可逐拍验证 | 需要权重装载、注入调度和结果缓存 | 推荐；具体协议见规格正文 |
| C. Weight-stationary 转置映射：PE(r,c)=B[c][r]，部分和向东、激活向南 | 计算期间权重保持不变 | 与本文采用的 `B[k][j]` 到 PE 的直接映射及数据流方向不同；需要在外部转置 B 或交换 A/B 的角色，验证更容易混淆 | 需要额外转置契约；V1 没有收益，暂不采用 |
| D. Output-stationary 或 input-stationary | PE 局部累加或输入驻留，控制直观 | 不满足“weight-stationary”这一已锁定要求；不作为 V1 的实现方案 | 与 V1 设计约束冲突；不采用 |

## 推荐方案与影响

- **推荐：方案 B。** 理由：
  - PE(r,c) 明确保存 `B[r][c]`（r 是 K 索引，c 是 N 索引），符合 weight-stationary 的“计算期间权重不变”。
  - 激活 A[i][r] 向东、部分和 C[i][c] 向南，每个 PE 寄存一级；`T_pe(i,r,c)=t0+5+4i+r+c` 使两条波前在同一 PE 同拍对齐。
  - 整矩阵接口只在接受沿采样 A/B，内部用缓存、调度器和结果缓存完成 24 拍计算；不把整矩阵接口误实现为单拍组合乘法。
  - 四个输出行以 4 拍间距串行使用同一条部分和通路，避免不同输出行的部分和在同一列混叠；16 个结果连续捕获。
  - 单任务、无队列和背压保持的状态机较小，便于先验证计算核，再在 V2/V3 扩展系统集成和 CDC。
- 对实现和验证的影响：
  - 规格定义 PE 映射、权重装载 4 拍、注入 16 拍、结果捕获 16 拍、响应 24 拍后有效、最早 25 拍握手、最小任务间隔 26 拍。
  - 参考模型使用行主序和 `B[K][N]` 布局。RTL 测试检查逐拍时序、valid 对齐，以及计算期间权重保持不变。
- 实施与验证方法：
  - 独立整数参考模型核对主样例和边界值；单 PE 测试覆盖符号、极值和 valid；阵列测试覆盖 16 个输出、背压、复位及连续任务；综合检查结构、资源和警告。
  - 上述验证尚未完成。

## 验证边界与后续约束

- 资源、最高频率、功耗、实际吞吐未测量；24/25/26 周期是结构延迟，不是时序签核或性能承诺。
- 具体仿真/综合工具对 signed 乘法的实现差异尚未在 RTL 中验证；规格已固定显式 16 位乘积和符号扩展，V1 必须核实。
- V2 开始实现前，需明确真实层的形状、权重方向、bias 和量化参数；本 ADR 只覆盖 V1 的 4×4 INT8 原始累加。
- 如果方案 B 被接受，后续若因综合/时序需要改变阵列映射，必须新建 ADR 替代本记录，保留本记录和旧规格。
